An Empirical Study of Harness Design for Coding Agents

把 coding agent 的 harness 拆成可独立消融的三个组件（planning、action space、context management），固定执行循环，在 SWE-Bench Verified 和 Terminal-Bench 2.1 上跨 4 个模型跑了 176 组匹配配置，覆盖 5 种上下文管理策略和 4 种上下文窗口预算。结论：上下文预算越紧，上下文管理收益越大，主要来自避免 context overflow；先做规则式 elision 再做 LLM 摘要的分级策略效率最优，而让被删内容可恢复几乎没人用、也没有精度收益。Planning 对弱模型是精度支架、对强模型变成省钱手段；预定义工具只对 bash 能力弱的模型有帮助，bash 熟练的模型用纯 bash 接口成本显著更低。轨迹分析进一步解释了各组件改变的是轨迹长度、停止位置还是动作粒度。

为什么值得读：这是目前对「harness 各组件到底各自值多少」做得最系统的组件级消融，上下文管理、token 预算、工具集设计三条线一次讲清。

→ https://arxiv.org/abs/2609.20804

Quantifying Overclaiming Propensity in Frontier LLM Agents

定义 agent「overclaim」为最终回复与自身上下文矛盾（不需要推测意图、与任务是否成功无关），并构建 OverclaimBench：5 个文件审查场景 + 轨迹级覆盖度测量 + 预埋缺陷。评测 8 个闭源前沿模型（在各自生产 CLI 里）和 4 个开源模型（统一 harness）：67.9% 的运行没读完要求审查的所有文件；在这些运行中 80.4%（各模型 59–96%）的最终回复有误导性；强制拆 subagent 提升了阅读覆盖率但残留的不完整审查仍大多误导；谎称完成审查的 agent 漏掉预埋缺陷的概率约为读全者的 1.8 倍。

为什么值得读：直击 agent 可靠性里最难自动发现的一类失败——最终报告不可信，给了一个与任务成功率正交、可复用的评测协议。

局限：只覆盖「文件审查」这一类任务，overclaim 率能否外推到编码/运维等其他长任务未验证。

→ https://arxiv.org/abs/2609.20812

Closed-World Resolution Against Tool Hallucination in LLM Agents

研究 agent 调用「根本不存在的工具」或传「schema 里没有的参数」这一类失败，给出 H1–H5 五类工具幻觉分类，并论证幻觉防御在因果上必须位于任何工具网关（gating）之前——幻觉调用不是任何网关做过的决策，网关结构上无法拒绝它。在 10 个托管模型、两种调用界面上测得 322 次真实幻觉，其中伪造工具调用集中在无约束的 raw-JSON 界面（34 vs 3），且模型规模无助（675B 与 7–8B 持平）。扩展到 MCP 场景后，多 server 合并命名空间带来第二类幻觉面（M1–M5），实测 154 次，包括在单注册表下干净的前沿模型；作者开源了 Hallucinated-Tools Benchmark。

为什么值得读：工具调用层的结构性失效分析加上 MCP 多 server 命名冲突的实测，直接影响你怎么设计工具注册表和调用校验顺序。

局限：提出的 resolver（注册表成员检查 + 签名校验）本身是 trivial baseline，论文价值主要在测量与分类而非方法。

→ https://arxiv.org/abs/2609.19425

SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness

在 harness 层做自动化「auto-research 循环」，跨大量异构环境搜索 harness 改进，最后存活下来四个可复用机制，分别覆盖动作执行、上下文压缩、观测处理和委派式阅读，组成 SoL-Pi。在 51 任务的 EdgeBench 上，SoL-Pi 与基线 Pi 表现相当，但记录的 token 流量降低 44.7–49.0%，API 成本降约三分之一；相对原生 Codex / Claude Code harness 估算每小时省 8.75–13.50 美元。

为什么值得读：把「harness 优化」本身自动化，并给出四个可迁移的省 token 机制和明确的成本数字，正好落在编排 + 上下文管理 + token 预算三点上。

局限：在自建 EdgeBench 上验证、依赖特定前沿模型，跨基准与跨模型的可迁移性只有作者自述。

→ https://arxiv.org/abs/2609.20519

COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization

把 agent 的「可复用 skill」优化建模为候选空间动态演化下的预算内序贯优化：用 contextual bandit 决定把有限的执行评测预算分配给哪些候选 skill，同时基于执行反馈做证据驱动的 skill 演化。在 6 个异构 agent benchmark、3 个目标模型上，COBRA-Skills 平均表现最优，相对 SkillOpt 降低 55–58% 的优化成本，每个 benchmark 只用 50 条独特优化样本。消融显示它对 harness 变化鲁棒，且用目标模型自身生成/精炼 skill 也有效。

为什么值得读：skill/上下文资产的自动化构建与预算分配，是 agent 长期能力积累的核心工程问题，这篇给了成本可控的做法且跨 harness 有效。

局限：skill 的收益仍依赖执行反馈质量，对没有可靠 verifier 的任务域如何用未讨论。

→ https://arxiv.org/abs/2609.11682

DeltaSelect: Affordable A/B Testing for Coding Agents

指出现有 coding agent benchmark 是为全面横向对比设计的，不适合开发过程中频繁的「基线 vs 候选」决策：重采样 DeepSWE 已发布的试验后发现，只有 19.5%（113 中的 22 个）任务的单次运行结果与全量成绩的第五百分位 Pearson 相关达到 0.50 以上。DeltaSelect 用相关性筛出「单次运行就能稳定追踪全量成绩」的任务，用线性回归把分数校准到统一尺度，并在给定美元预算内选出固定任务集。案例中改 skill 与 instructions 共 13 次评测总花费 27.86 美元，最终采纳版本比初始版本成本低 58.1%（1.75 vs 4.18 美元，p=0.008），校准分数从 36.46% 升到 42.36%。

为什么值得读：给了一个把 agent 评测成本压进日常开发迭代的可操作方法，直击「评测贵且噪声大」这个卡住 harness/prompt 迭代的实际瓶颈。

局限：任务子集的相关性是在特定模型+harness 上标定的，换模型或换 harness 后需重新选集；案例研究只有一个。

→ https://arxiv.org/abs/2609.19607
