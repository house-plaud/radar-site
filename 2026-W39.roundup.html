  • NVIDIA Nemotron 3.5 Lightning — 30B MoE、每 token 激活约 3B 参数，面向 agent 工作流中高频的读文件/选工具/校验结果类调用，开放权重可本地部署。 原文

Jev 与「决策模型」（System One）

  • Jev 是什么 — TypeSafe 的决策模型：输入一段文本加一个带类型的问题，返回预定义选项中的一个、置信度及每个选项的概率；三个原语 Choice、Score、Noul；文中给出定价与上下文窗口，并说明不开源。 原文
  • Jev vs 生成式 LLM 的适用边界 — 以每月 4 万张工单的三重分类（归类、是否升级、回复）为例做基准对比；结论是「答案属于 N 选一」用 Jev、需要散文输出用 LLM，并可用 Jev 先路由、代码算、LLM 写，或用 Jev 复核 LLM 输出。 原文
  • Jev 与 Claude Opus 5 的分类准确率实测 — 在 Banking77 上跑了 3,080 条客服样本，对比准确率、延迟与成本，并讨论按 Jev 置信度做路由的做法及其局限。 原文
  • 用 TypeScript 调 Jev 做内容审核 — 以市场平台的商品列表审核为例，讲状态对象怎么组织、问题类型怎么选、评判标准怎么写才经得起字面理解，以及如何用带标注样本定 publish/hold/reject 的置信度阈值。 原文
  • TypeSafe CEO Diogo Almeida 长播客（2h20m） — InstructGPT 共同作者，长期主张 API 前沿模型在对齐、拒答、可靠性上走错了路；本期为 Jev 的作者视角完整阐述。 原文
  • Arize：Jev vs LLM-as-a-Judge 基准 — 对比 Claude Opus 5 和 GPT-5.6 Terra 的准确率、成本、延迟，称 Jev 约便宜 300 倍，并分析阈值调整如何改变幻觉检测效果。 原文
  • Arize：用 Jev 做实时护栏 — 与 GPT-5.4 nano 对比延迟与成本，检查对象包括 agent 输入、回复和工具调用。 原文
  • 在 Arize AX 中用 Jev 搭远程评估器 — FastAPI 实现的 remote evaluator，返回 label 和 score，并说明如何从自己的数据选阈值。 原文

  • Cloudflare Worker Previews — 每个 Git 分支获得一个接近生产的隔离环境，拥有独立代码、配置、URL、可观测性和状态，面向 agent 产生的大量变更做发布前验证。 原文

  • Klaviyo 两周内在 Vercel 上线 356 个内部应用 — 2,000+ 员工中有 512 人参与「公民开发者」计划，其中 196 个是自带数据库的全栈应用；应用默认私有并经 SSO 门控，从想法到上线约 3 分钟；使用部门包括法务、市场、HR。 原文
