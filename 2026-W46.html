When Routine Operations Break Architectural Pattern Relationships in LLM Agent Harnesses

研究五个已发布 agent harness 和 14 个独立插件，用 PatternOps 追踪 Guardrail Enforcement Point、Autonomy Controller、Blackboard 等模式关系。发现重载插件、保存 allow rule 等日常操作会在不修改代码的情况下静默破坏模式关系，导致策略停止评估编辑、禁止编辑被执行。结论是模式关系属于运行系统及其历史，需按部署的决策路径、状态生命周期与操作序列来评估。

为什么值得读：直接揭示 agent harness 中 guardrail/状态关系会被日常配置操作悄然破坏，正是编排与可靠性要处理的问题。

局限：小样本（5 个 harness、14 个插件）且无量化失败率，部分结论依赖特定实现路径。

→ https://arxiv.org/abs/2611.09088

When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents

在三个真实开源仓库的 stale instructions（AGENTS.md/CLAUDE.md）上，让两个模型执行 22 个维护任务，分析 732 条轨迹。发现 agent 在相关信息存在时仍会跟随过期指引；以 stale test command 为例，Claude Sonnet 5.5 每次约多出两次工具调用，成本比修正后高三分之一。所有 agent 都能从即时失败中恢复，但无一修复底层的 instruction file。

为什么值得读：说明上下文/instruction file 的技术债如何转化为每个 agent session 的隐藏成本，贴合上下文管理。

局限：仅深入 3 条真实指令、两个模型，且另两个案例未检测到显著差异。

→ https://arxiv.org/abs/2611.09802

Aegis OS: A Transactional Multi-Tenant Operating System Runtime for Eliminating Authorization Fatigue in Autonomous Coding Agents

Aegis OS 把授权边界从单次工具调用移到事务性工作区边界，用内核强制沙箱、CoW 影子工作区、身份固定 HTTP egress 代理和 A2A IPC/CAS 实现。在 1,500 次受控调用与 28,087 次真实调用（52 个 session）中，将确认提示减少 90.7–97.9%，真实 session 中断率仅 1.12%，同时降低 80 次攻击的成功率，并解决多 agent 共写工作树与内联大 artifact 的高 token 开销。

为什么值得读：同时覆盖授权疲劳、多租户工作区隔离和大 artifact token 开销，且有真实 session 规模数字。

局限：主要基于 52 个 coding sessions/80 次攻击，未体现更大规模生产集群；依赖 macOS/Linux 内核机制。

→ https://arxiv.org/abs/2611.08516

FlowPlan: Reducing the Token Cost of Coding Agents with Abstraction-Guided Planning and Verification

FlowPlan 让 agent 在 per-function 控制流/数据流图上做定位、规划和验证，先给出 graph deltas 再改源码，并在完成后比较结构化变化。六个 benchmark-model 组合中，解析率与 vanilla agent 无显著变化，但每个设定的 token 消耗都下降；Claude Haiku 4.5 在 SWE-bench Verified 上仅用 baseline 的 0.32–0.35x tokens。

为什么值得读：证明可通过抽象层面的规划/验证直接削减编码 agent 的 token 预算，而不牺牲成功率。

局限：分辨率没有提升，且只在 SWE-bench Pro/Verified、SecBench 上验证了 2 个模型。

→ https://arxiv.org/abs/2611.13241

Comparative Analysis of Agent Evaluation Frameworks: Stability, Detection, and Discovery in Enterprise Analytics Agents

在企业分析 agent 的冻结执行轨迹上比较三类评估框架：基于 trace 的 LLM 评判、纯文本 LLM 评判+red-teaming、确定性启发式。97% 配置满足稳定性阈值；trace-based 框架达到最佳精确率-召回平衡 F1=0.90，纯文本 recall 相当但误报多 5 倍。第三阶段发现 24 个新失败，功能性测试与安全 red-teaming 零重叠。

为什么值得读：给出可操作的 agent 评估框架选择策略：功能评估用 trace-based，安全用 red-teaming。

局限：受控冻结 trace、两个 agent；未在实时工作流中验证。

→ https://arxiv.org/abs/2611.14493

Measuring Tabular Data Formats Cold: A Replicated Cold-Cache Benchmark of Serialization, Scan, and Index Performance on Real Datasets

在 NYC taxi 与美国航空准点两个真实数据集上，以显式冷缓存、随机执行顺序、三独立 session 对 15 种格式/访问路径配置做基准。Parquet 过滤聚合比 CSV 快 2.6–11 倍，JSON Lines 慢 10–27 倍；随机序数据上二级索引使 SQLite 查询慢 2.6–4.8 倍，仅对有序低选择性有帮助。4GB 低内存主机会反转部分排序，提示内存环境影响格式选择。

为什么值得读：非 AI 系统设计里很扎实的存储格式性能取舍，带冷缓存和统计校正方法论。

局限：只覆盖单机笔记本/服务器环境与两个数据集，不涉及分布式/云存储。

→ https://arxiv.org/abs/2611.10398
