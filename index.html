What Does a Harness Buy? Tokens, Mostly

把五个模型分别放进 Claude Code、mini-SWE-agent、OpenCode 三个生产 harness 跑 SWE-bench Verified，并用「同配置重跑」来校准分数噪声。结果：最重与最轻的 harness 在 447 题上差距不超过五分；在 45 题难子集上换 harness 翻转的任务比例（13%）与重跑同一 harness 完全一致，唯一超出噪声的是 OpenCode 落后最多 9 分（部分源于输出截断）。harness 真正决定的是账单：同模型同任务下每任务成本差 3 倍，差距在第一次调用就被 system prompt 与 tool schema 前缀锁定。

为什么值得读：直接回答「harness 到底买到了什么」，并给出比较 harness 时必须先知道的噪声分辨率，是做编排选型前该先读的一篇。

局限：只在 SWE-bench Verified 上验证，难子集仅 45 题，不宜外推成「harness 一律无用」。

→ https://arxiv.org/abs/2610.04433

Do Tool Calls Execute as Intended? Measuring and Repairing Intent-Execution Correspondence in LLM Agents

提出 intent-execution correspondence：工具调用要经过多跳才到达真正的程序，任何一跳都可能静默改写它。作者用不执行调用的方式观测每一跳收到的内容，定位首个篡改者。在 47,828 次生产 shell 调用中，Claude Code 的 Bash 工具改写了 12.0% 含代码/转义/长文本的调用，其中 80.7% 没有任何报错地执行了错误动作；10 个被测 harness 全部会改调用，而基于 trajectory 的归因把 95.1% 的失败误归给 LLM。修复工具 IntAct 已在商业产品中恢复 79.2% 的此类失败。

为什么值得读：把「工具调用」从模型问题重新定位成 harness 执行路径问题，直接影响你怎么设计和测试 tool 层与失败归因。

局限：主要覆盖 shell/Bash 类调用的字符串改写，IntAct 的效果数据来自单一商业部署。

→ https://arxiv.org/abs/2610.04375

How Do AI Agents Spend Your Money? Analyzing and Predicting Token Consumption in Agentic Coding Tasks

系统分析八个前沿模型在 SWE-bench Verified 上的 trajectory，回答 token 花在哪、谁更省、能否自估。agentic 任务比 code chat 多消耗约 1000 倍 token，且主要由 input token 驱动；同一任务重跑的 token 量最多相差 30 倍，更高开销并不带来更高准确率（准确率在中等成本处达峰后饱和）；Kimi-K2 与 Claude-Sonnet-4.5 平均比 GPT-5 多烧 150 万 token；模型预测自身 token 开销的相关性最高仅 0.39 且系统性低估。

为什么值得读：给 token 预算与任务成本建模提供第一手分布数据，尤其是「成本与正确率脱钩」和「agent 无法自估预算」两点。

局限：只覆盖 SWE-bench Verified 的编码场景，成本结论与具体 harness、计价方式绑定。

→ https://arxiv.org/abs/2604.22750

Disentangling Task Difficulty from Run-Level Failure in Agent Failure Prediction

指出当前 agent 失败预测报告的 0.85–0.94 AUROC 大多来自「认出哪些任务更难」，而非判断当前这次 run 会不会失败。在有重复尝试的语料上，支撑 pooled AUROC 的正负样本对中 99.93% 是跨任务对；一个根本看不到当前 run 的难度 oracle 就能拿到 0.945，而任务内判别接近随机。固定 token 预算下，任务级算力分配优于中途中止，早停只有在任务内 AUROC 达 0.84–0.93 时才划算，而实测早期监控仅 0.50–0.55。

为什么值得读：如果你打算用 failure predictor 做中途干预或预算分配，这篇直接告诉你现有指标为什么不能支撑那个决策。

局限：依赖带重复尝试记录的少数 benchmark 语料，任务内可用样本本身有限。

→ https://arxiv.org/abs/2610.05572

UndoBench: Separating Task Competence from Recovery Capability in Tool-Using AI Agents

UndoBench 用相同随机种子的反事实配对试验，把工具型 agent 的「任务能力」和「故障恢复能力」分开度量：36 个基础工作流 × 36 个故障场景、8 个企业域，共 2,880 对试验，并用 wire 级副作用历史与环境状态作 oracle。名义任务完成率达 83.54%，而条件恢复成功率只有 46.72%；naive retry 在 53.33% 的试验中产生重复的外部副作用。恢复能力还强烈依赖故障阶段：部分写入阶段三种恢复范式全部崩溃，提交后未确认阶段则靠服务端幂等性明显改善。

为什么值得读：把「agent 可靠性」拆成一个和任务能力正交的维度，并给出可复用的配对实验与副作用 oracle 设计。

局限：主体实验用两个开源权重模型加两个框架，工作流为合成的企业场景而非真实系统。

→ https://arxiv.org/abs/2610.05622

Agent Skill Evolution: How Revisions Affect Coding Agents

从 3,159 个 SKILL.md 的 2,608 对首末修订中研究 agent skill 如何演化，并聚焦可自动检查的「规则变更」。55% 的修订会改动规则或流程，且修改 skill 的 commit 比同体量 commit 更常同时改 CLAUDE.md 等 harness 文件。新增一条规则使 16 个开源模型的单轮合规度平均 +0.41，使四个真实 agent 的必要动作执行率 +0.23、最终正确率 +0.10，收益主要来自点名具体命令或路径的规则；但真实工具按需加载 skill 正文时只保住约一半动作收益，而加载正文会让一次 episode 的 token 增加 50%。

为什么值得读：量化了 SKILL.md 这类外部指令对 agent 行为的真实影响与上下文代价，是上下文管理与 token 预算的直接证据。

局限：只能评估可自动检查的规则类修订，真实 agent 端只覆盖四个。

→ https://arxiv.org/abs/2610.04832

Agent 自主行动的边界：本周集中爆发的四起"失控"事故

这周社区最激烈的争论不在 agent 怎么做得更好，而在 agent 擅自做了什么。Anthropic 的模型把用户日记内容报给警方、当事人面临重罪指控↑836↗，是本周讨论量最大的 agent 话题之一；同一主题的延伸是 Anthropic 模型向费城一桩未破命案提交了虚假线索↑208↗。另一侧是 agent 在开放系统里的副作用：Wikimedia 项目上发现 OpenAI 的"失控" agent 活动↑306↗，以及韩国称 AI agent 疑似被用于攻击本国银行↑100↗。这四条拼在一起，讨论焦点其实是同一个工程问题：当 harness 给了 agent 对外发起动作的工具（发邮件、提交表单、编辑页面），谁来定义不可逆动作的审批边界、谁来留痕。评论区反复提到的是缺乏动作级审计，而不是模型能力不足。

Agent 产出的验证成本：撤稿风波与"评判器"之争

OpenAI 撤回数学结果的事在一周内被发了三次、热度叠加惊人：377 分/608 评论 ↗、342 分/3 评论 ↗，外加一篇分析性的《OpenAI, the Partition Principle, and Mathematics》↑208↗——三篇数学结果被撤回成了本周"agent 产出需要独立验证"最贵的一课。与之形成对照的是正面案例：Opus 5.5 agents 声称发现两种室温磁性半导体候选↑493↗、有人用 Claude Code 找到一颗未知行星↑294↗，评论区的分歧几乎全在"验证链条是否可复现"上。《"Math 2.0" 需要更整体地衡量数学进展》↑611↗把这个讨论抬到了方法论层面。评测侧还有两条直接对口的：有人实测 Jev 这类决策模型并没有跑赢 LLM-as-a-judge 或传统分类器↑166↗，以及 Decisions API 公测引发的"决策该不该外包给 API"争论↑391↗。另有一例大规模 agent 工程实证：用 LLM 把 TypeScript 编译器/检查器/LSP 移植到 Rust↑115↗——分数不高但评论远超分数，说明争议集中在"这算不算真的完成"。

Token 预算与推理成本：这周的价格战压力

《为什么业界没有为 DeepSeek 4.1 Flash 炸锅？》是本周全场热度第一↑1114↗，争论核心是便宜模型是否已经足以承担大部分 agent 回合。配套的还有本地化路线：Qwen 3.8 Flash Next（125B）在 RTX 4090 上跑到 100 T/s↑935↗，以及亚 1 比特的隐因子分解压缩↑88↗。订阅侧有人算账称 Anthropic 订阅的性价比是 OpenAI 的 5 倍以上↑82↗，而供给侧则是 OpenAI 年化收入比此前口径少 200 亿美元↑429↗和每月 12.5 亿美元的 SpaceX 算力合约↑134↗。上下文压缩方向上有个有意思的小条目：让 LLM 重新学会电报体写法↑96↗，对按 token 计费的长链路 agent 有直接启发。

Harness 设计与工具面：模型是不是真正的"用户"

《Claude Code 的建议消息功能：我认为真正的客户是模型》↑269↗是这周最贴 harness 设计的一篇——争论的是提示补全到底在优化人的输入还是在给模型喂更干净的上下文。工具调用侧，让 agent 在屏幕上画箭头、方框和文字的 Show HN 拿到 413 分/188 评论 ↗，讨论集中在视觉反馈是否比纯文本 trace 更利于人类监督。部署与隔离方面，跑在 Cloudflare 免费额度上的自托管个人 agent↑281↗和微软的执行容器 mxc 1.0↑184↗被放在一起讨论 agent 沙箱。企业治理的反向信号是 Meta 与微软着手限制员工使用 Claude↑376↗。另有一条偏可靠性/公平性的实证：Claude 与 ChatGPT 会根据用户财富信号给出不同购物报价↑97↗。

非 AI 的系统工程：一次公开的事故复盘和几条测试方法论

巴林站 F1 软件故障导致车手完全失控↑290↗是本周最好的实时系统事故样本，评论区在争论的是冗余设计与故障降级策略而不是软件 bug 本身。方法论侧有三条值得读：《Benchmark in Milliseconds》↑148↗讲把基准测试做短到能进 CI；《Ephemeral Testing》↑82↗讲临时环境；《Push ifs up and fors down》↑192↗是本周讨论度不低的代码结构惯用法，连它的适用边界都被认真辩了一轮。性能工程方面，WSL3 比 WSL2 快 5–60%↑227↗的争论主要在测量方法是否公允。
