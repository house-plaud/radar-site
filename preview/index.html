Addy Osmani · 2026-09-14 · 周末整块

Jev vs LLM-as-a-Judge

Jev introduces a new shape of LLM - System One, aka Decision Models

Simon Willison · 2026-09-21 · 碎片时间

Simon Willison 介绍 TypeSafe AI 发布的 Jev 模型，这是一类新的「System One 模型」（或叫「决策模型」）的首个实例。Jev 接收文本输入但输出浮点数对应的分类、是/否问题、评分和置信度，而非文本，定价仅 $0.042/百万 tokens（便宜于 GPT-5 Nano），且输出免费。这种结构化输出模型对 agent 评测和决策链的成本优化有直接价值。

社区在聊什么

前沿模型集中发布，争论从"能力"转向"这对 agent 编排意味着什么"

这周的讨论被几场模型更新占满：Claude Opus 5.5↑1562↗、GPT-6 Sol and Luna↑1551↗、Grok 4.7↑603——把模型放进 token 预算和单任务成本的坐标系里，才是工程侧关心的读法。与之相对，GPT-6 Astra 破解 2005 年以来未解的 Enigma 报文↑663↗和 Did OpenAI solve the wrong Navier-Stokes problem?↑108↗构成了一组对照：社区在追问"宣称的突破，验证条件到底是什么"，这与 agent 评测里的老问题同源。

agent 真正落地时撞上的墙：权限、平台对抗与"提示词到底是不是抽象层"

最有系统设计味道的一条是 Amazon 封禁 Meta 的 Muse AI agent 在 amazon.com 上购物↑151↗——评论数超过分数，说明这是纯争论帖：agent 作为第三方客户端访问别人平台，究竟算用户代理还是未授权抓取，社区没有共识，这直接决定了消费级 agent harness 的可用工具集边界。同一条线上还有 Unreal Agent↑187↗和 Show HN: CUA-S1 – A System One Model for Computer Use↑93↗，后者分数不低但只有 10 条评论，典型的"看着有意思但没人真在用"。抽象层这一侧，Prompts aren't Real↑117↗质疑把提示词当稳定接口的做法，对任何在做上下文管理和 prompt 版本化的人都值得一读；而 ChatGPT 通过广告采集器获知你在其他网站的行为↑758↗把"上下文从哪来"这个技术问题变成了信任问题。

评测与可靠性：可复现性成为本周的共同焦虑

这是最贴他方向的一簇。Show HN: JevBench, a reproducible benchmark for typed decision models↑109↗和 Hugging Face 上 UK AISI 与 EvalEval 合作让基准结果可复现 ↗指向同一件事：基准分数不可复现已经不是学术洁癖，而是被当成工程缺陷来修。反方向的声音同样密集——LLM Ass Bench↑155↗以调侃姿态质疑基准本身，2023 年的老文 The LLMentalist Effect 被重新顶上来↑230↗、评论数远超分数，配合 The Claude Delusion↑95↗同样是评论近分数两倍，说明"我们是不是在给冷读术打分"这个质疑在这周被重新点燃。可靠性的现实一面则是 Elevated errors for multiple models – Resolved↑139↗——一次多模型供应商侧故障，对把 LLM 当依赖项的 agent 系统来说就是一次教科书级的事故复盘素材。

小模型、本地推理与"每次决策花多少钱"

围绕 Jev 系的讨论形成了一个小生态：Kev: Tiny Jev-like family of decision models built on top of Qwen3.5↑457↗、OpenAI is well positioned to fast-follow Jev↑294↗，加上前面提到的 JevBench。争论点是典型的架构取舍：用小而专的"决策模型"承担 agent 流程里的路由与判断，能不能把 token 预算压下来，同时不让可靠性塌方——fast-follow 那条 208 条评论对 294 分，说明社区更关心"小模型这条路会不会被大厂一口吃掉"而不是技术本身。配套的还有 Show HN: Mini-AGI – 在 8GB 显存上训练的动态持续学习模型↑276↗、Can gzip be a language model?↑390↗这种把"模型"下限往回推的思想实验，以及 Pirate Face Rescues LLM Models from Deletion↑563↗——权重会消失，这对任何把特定模型版本写进生产 pipeline 的人都是供应链风险。硬件侧 M5 Ultra Mac Studio Review↑264↗评论数几乎等于分数，本地推理的性价比依旧吵不出结论。

非 AI 的系统与性能工程：这周量不大但质量高

AMD Ryzen 两年内如何快了 50%↑345↗是本周最扎实的性能工程贴，讲的是在同一套约束下靠持续的微架构改进累积出 50% 这种量级的收益，方法论上和"给 agent 系统做逐层降本"是一回事。遗留系统与兼容层方向有 Microsoft killed FoxPro in 2007.   • Jev 播客：TypeSafe AI CEO Diogo Almeida — InstructGPT 共同作者，长期主张 API 可用的前沿模型走错了方向（对齐、拒答、可靠性）；节目定位为"System One models for Prod, not God"，时长约 2 小时 20 分。 原文
  • What Is Jev：决策模型的三个原语 — 输入文本 + 带类型的问题，返回预定义选项之一、置信度以及每个选项的概率，走 Decisions API 而非 chat endpoint。三种原语为 Choice、Score、Noul（是非）。文中覆盖概率读法、定价与上下文窗口、是否开源。 原文
  • Jev vs LLM：何时该用决策模型 — 以月均 4 万张工单的三问题триaж（分类、是否升级、回复内容）为例做对比基准：答案属于 N 选一时用 Jev，需要散文输出时用 LLM；推荐模式是 Jev 路由、代码计算、LLM 撰写，并用 Jev 在发布前校验 LLM 输出；阈值需从自有数据确定。 原文

CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents

CliffCompaction 提出一种长时程编码 agent 的上下文自动压缩方法：只做截断和丢弃、绝不改写或复述原文，且每次压缩只作用于原始内容、不对压缩结果再压缩，从而避免上下文漂移累积。在有界上下文下成本最多降低 50%，同时在 Terminal-Bench 上性能持平或更好；配合并行 test-time scaling 后，Kimi K2.6 可追平 Opus 4.7 且成本更低。在 KernelBench 上跨百万 token 会话持续学习，200 步达 2.23× CUDA 加速、400 步 3.58×，超过专门的搜索算法与训练过的 agent。作者开源了与 scaffold 无关的 API-proxy 实现，可直接接 Claude Code / Codex。

为什么值得读：直击上下文管理与 token 预算：一个可即插即用、且把「压缩保真性」讲清楚的 compaction 机制。

→ https://arxiv.org/abs/2609.26779

Grow the Harness, Not the Context: From Strategy-Free Scaffolds to Reusable Specialist Agents

Growing Harness 主张把反复出现的控制逻辑从模型上下文中搬到可执行代码里：从一个只暴露模型与工具接口、不含任何任务控制器的「无策略脚手架」出发，用函数级执行 trace 把每次失败定位到有界代码面，优化器批量修复一窗口失败，并用 success-first 的 held-out 门控回滚有害改动，所有改动累积进同一个共享 harness。在 BrowseComp-Plus 与 WebArena-Verified、4B 到 120B 三种部署模型的六个组合中，五个取得最高平均成功率，相比 Tool-Calling agent 减少 76.0–91.8% 的 LLM 调用、74.4–98.6% 的推理成本；WebArena-Verified 上跨模型规模稳定在 44.7–45.3%，而 Tool-Calling 在 4B 模型上掉到 6.7%。

为什么值得读：harness 自身可被训练出来这一路线的干净样本，且把「控制搬出上下文」换算成了明确的调用数与成本收益。

→ https://arxiv.org/abs/2609.26760

FIRE: Failure-Informed Runtime Engineering for Reliable Language-Model Agents

FIRE 研究的是 harness 层的运行时策略：在曾导致失败的状态上注入定向自然语言指令或直接拒绝某些动作，不改权重也不改用户 prompt。在完整的 87 题 Terminal-Bench 2.1 上每题两次尝试，三个 GPT-5.6 档位的 pass^2 全部提升，Sol 的 best-of-two 只涨 1.2 个点而重复成功率涨了 9.2 个点，说明策略主要是把「已能做到」转成「稳定交付」；策略加持的 Terra 以约一半成本超过无辅助的 Sol。五臂随机实验中真实策略 61%，无策略 39%、时间匹配的安慰剂 36%、泛化验证/重新考虑提示 39–43%，且 24 次策略尝试中 22 次出现了预期的纠正行为。

为什么值得读：把「可靠性」和「能力」分开度量（pass^2 vs best-of-n），并用对照实验证明 harness 层干预的机制有效性——agent 可靠性工程的范本。

局限：策略是针对已观测失败状态人工/半自动构造的，跨任务分布的可迁移性未验证。

→ https://arxiv.org/abs/2609.26048

RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

RRSI 指出 agent harness 的递归自改进容易记忆训练任务、in-distribution 大涨而 OOD 归零，因而给提议与选择两端都加上正则：提议器用随时间退火的编辑预算限制单个候选能捆绑多少改动并鼓励未探索轨迹，选择器配 critic 筛掉 benchmark-specific 提议、配 pruner 删掉过小/过贵/失效的改动。在覆盖编码、agentic workspace 与工程设计的八个 benchmark 上，演化所用的 split 上最多 +14.1 分，五个 OOD benchmark 上最多只有 +4.7 分，同时产出的 harness 少用 30% policy token。代码已开源。

为什么值得读：harness 自动演化这条线最该警惕的过拟合问题，附带可复用的提议/选择正则化设计与 token 开销对比。

→ https://arxiv.org/abs/2609.24972

Recursive self-improvement of AI research agents

AIDE^2 让一个前沿 AI 研究 agent 改写自己的代码：提议改动、在一组 AI R&D 任务上对改后版本做基准测试、按隐藏评测保留最好的版本，被接受的改写成为下一轮被编辑的 agent。在一次自主运行 8 天的循环中发现了 7 项连续改进，包括新的搜索策略和压缩/管理不断增长上下文的记忆机制；这些收益迁移到四个 held-out benchmark（含分布外的物理天气预报），最强版本追平或超过一个排名靠前的人工工程化生产级研究 agent。另外在一个独立 held-out 任务族上 reward hacking 率从 55% 降到 32%，比人工 agent 还低 7 个百分点，而循环从未显式优化这一点。

为什么值得读：看自动演化实际「发现」了哪些 harness 机制（搜索策略、上下文压缩记忆），比读人写的设计更能反映什么真的有用。

局限：单次 8 天运行、单一 agent 系列，结论依赖特定基座与任务套件，难说可复现。

→ https://arxiv.org/abs/2609.26457

Measuring the Serving Stack Instead of the Model: Hidden Confounds in Local Tool-Use Evaluation

本文指出本地部署栈会污染工具调用能力的评测结论：Ollama 中 tools= 请求由每模型的静态模板 flag 决定，有的模型以文本形式返回调用、有的走原生 tool_calls，而 Phi-3 和 Gemma-3 在推理前就被直接拒绝；若 harness 不把拒绝和重试耗尽保留为结构化失败元数据，下游分析会把它们误判为模型不调用并天真地报出 0% 的调用保真度。在保留原生通道的同时附加文本工具列表能恢复大部分保真度，而统一走文本协议反而会拉低本身支持原生调用的 Llama-3.2；跨 Ollama、llama.cpp、vLLM、SGLang 的探测显示同一请求处理方式各异，约束解码消除解析失败却可能导致不终止，turn-pooled 与 per-instance 估计相差可达约 55 个点。

为什么值得读：做 agent 评测时最容易被忽略的混淆源，附带一份把 serving 行为纳入评测协议的检查清单。

局限：只覆盖本地开源部署栈与少数小模型，对调用托管 API 的场景参考价值有限。

→ https://arxiv.org/abs/2609.26693
