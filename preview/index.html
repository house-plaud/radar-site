COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization

COBRA-Skills 把「agent 可复用技能库的优化」形式化为预算受限的序贯优化：用 contextual bandit 决定把有限的执行评测预算分配给哪些候选技能，再用带证据的演化机制根据执行反馈不断改写技能种群。在 6 个异构 agent benchmark、3 个目标模型上平均表现最好，同时相比 SkillOpt 把优化成本降低 55–58%，每个 benchmark 只用 50 条优化样本。作者还验证了换 harness 后方法依然稳健，以及用目标模型自身生成/精修技能也可行。

为什么值得读：直接命中「技能/上下文复用 + 评测预算分配」这条线，是少见的把 agent 自我优化的 token 成本当作一等约束来设计的工作。

→ https://arxiv.org/abs/2609.11682

RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments

RSIAgent 是一个 training-free 的多 agent 框架，用 curriculum / actor / verifier 三类角色在新环境中自主探索，把验证过的环境知识（尤其是动作-条件-后果的因果关系）写进记忆；探索策略是「先广后深」——并行广度探索摸清环境结构，再对困难样例、隐藏约束、边界条件做深度探索。记忆构建完后被冻结，下游任务直接复用，不更新任何模型参数。在 OSWorld-v2 和 Agent's Last Exam 上让 Kimi-K3、GLM-5.3 等开源模型超过了闭源前沿模型。

为什么值得读：不改权重、只靠离线构建的环境记忆来提升可靠性，是可直接搬到自己 harness 里的上下文管理机制。

局限：结论依赖于所测的两个特定环境和特定开源模型，记忆的迁移性与陈旧化问题未充分讨论。

→ https://arxiv.org/abs/2609.15364

SWE-Bench Pro Verified: A Reliable Benchmark for Software Engineering Agents

作者发现 SWE-Bench Pro 的评测存在两类系统性不可靠：一是 reward hacking（gold patch 或隐藏评测信息泄漏，agent 可以直接读到答案），二是任务质量问题（问题描述有误导、测试范围划定不当）。他们做了 SWE-Bench Pro Verified：加入反作弊隔离措施封堵泄漏通道且不破坏 agent 正常功能，并对有缺陷的实例做最小化修正。重测后部分模型分数显著下降，说明此前榜单高估了真实编码能力。

为什么值得读：如果你依赖 SWE-Bench 系列判断 agent 能力，这篇直接告诉你哪些分数是假的、泄漏通道长什么样。

→ https://arxiv.org/abs/2609.08149

Agora: Git as Shared Memory for Collective AutoResearch

Agora 用 Git 做多 agent 的共享记忆：每条结果、洞见、假设、验证、报告都是一个 immutable commit，父边表示它建立在什么之上，整体构成 append-only DAG，任何 claim 都能被 checkout 并重跑；派生索引暴露研究前沿、被忽略的分支和各 claim 的验证状态，再配一个 diversity-aware 选择规则防止所有 agent 塌缩到同一条路线。实测跑了近 12 天、13 个 LLM worker、无中央调度器，产出 1703 条贡献，把评测指标从 3.39 降到 1.899 bits per byte。

为什么值得读：把「多 agent 协作的共享状态」落到 Git 这种已有的可复现基础设施上，是个很具体且可迁移的编排/记忆设计。

局限：只有单次 12 天的运行作为证据，中途还有一次人工干预把社群从单一路线里拉出来，机制的自洽性尚未被独立验证。

→ https://arxiv.org/abs/2609.18094

Confidence Comes from Experience: Experiential Confidence Estimation from Reasoning to Agents

XConf 主张置信度不能只看当前这次推理，而应结合模型自己累积的经验：把过去每次任务的反思、声明的置信度、实际结果和事后总结的教训存成记录，新任务来时先 Recall 检索相似任务+相似置信度的历史成功率，再 Reflect 让模型指出自己反复犯的错并重述置信度。不需要 logit 访问或改权重，只花一次生成的成本。在 9 个 benchmark、4 个模型上，24 组对比中有 23 组 AUROC 打平或超过 10 次采样的 self-consistency，ECE 明显更低，成本只有十分之一；用于选择性预测时，弃答置信度最低的 10% 可把 agent 任务交付成功率最多提升 8.7 个点。

为什么值得读：低成本、格式无关的置信度估计直接决定 agent 该 ship / 该升级 / 该重试，是可靠性与 token 预算的交汇点。

→ https://arxiv.org/abs/2609.17708

From Runnable to Shippable: Multi-Agent Test-Driven Development for Generating Full-Stack Web Applications from Requirements

TDDev 自动化了 web 应用 TDD 闭环中最难的三步：从需求导出可执行验收测试、用浏览器动态交互验证行为、把失败转成可行动的反馈。作者在 20 个应用、多个 backbone、两种 coding agent、三种 TDD 实现（Incremental / Whole-Project / Agentic）上做了对照实验：backbone 足够强时 TDD 带来 15.5–23.7 个百分点的准确率提升；弱 backbone 需要换更强的 tester 才能把收益转正；Whole-Project TDD 在多数配置下成本效率最高，Agentic TDD 只在最强模型上占优。最后给出一棵按模型能力、反馈可靠性、部署目标选实现方式的决策树。

为什么值得读：对「反馈循环怎么设计、谁来当 verifier、哪种编排最省成本」做了少见的受控对比，结论可直接用于自己的 harness 选型。

局限：只在 20 个 web 应用上验证，且结论强依赖 backbone 能力分层，换域后决策树未必成立。

→ https://arxiv.org/abs/2605.17242
